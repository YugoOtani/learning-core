# 実装の好み

更新日：2026-10-03
適用範囲：プロジェクトをまたいだ実装・修正・レビューの既定の好み。

## 共通の要点

- 現在の要求を満たす、最小限で一貫した実装を好む。将来のためだけの抽象化や、今回扱わないケースへの対応を増やさない。
- 既存の設計・命名・コードスタイルを尊重し、関係のないリファクタリングを行わない。
- 意味のある処理単位、命名、型、データ構造によって意図が分かるコードにする。
- AIが書いたコードについても、人間が実装方針と変更の意味を理解し、レビューできる状態を重視する。
- コメントは自然な日本語で書く。設計理由に加え、理解を助ける処理ブロックの要約も必要に応じて使う。
- 検証は外部から観測できる振る舞いを中心に行い、実行していない検証を成功として報告しない。

毎回すべての文書を読む必要はない。今回の作業に関係する文書を参照する。

## 適用と更新

このメモリは好みの既定値を表す。今回のユーザー指示やプロジェクト固有の仕様・制約と照合して適用する。最小実装を理由に、要求を満たすために必要な処理を省かない。

以下は、この初期メモリを維持するための運用方針であり、過去のチャットから判明した好みとは区別する。

- ユーザーから保存・修正を依頼された内容は、該当する文書に反映する。
- 作業中に新しい好みらしきものを見つけただけでは、恒久的なルールとして追記しない。
- 今回だけの指定は、その適用範囲を残す。AIが提案しただけの案をユーザーの好みにしない。
- 古い記述と新しい明示的な訂正が矛盾する場合は、古い記述を更新し、両方を有効なルールとして残さない。
- 新しい分類が必要になるまでは、既存の文書に短く追記する。
